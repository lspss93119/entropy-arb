# P0-03：未知成交時的人工復核流程（草案）

> 適用範圍：`entropy-arb` 在雙腿成交、訂單接受狀態或對帳結果不確定時。這是 Draft PR #6 的配套操作文件，**不代表程式已可部署**。

1. **停止新的套利開倉**。出現 `unresolved`／`send-unknown`／未預期執行例外時，保持交易暫停；不可因舊的本地 position 或 CSV 看到 `filled_base=0` 就判定未成交。
2. **確認沒有其他執行程序**，檢查兩個交易所是否還有活動或未知結果的訂單。若訂單仍可能稍後成交，先以交易所介面／權威訂單查詢確認終態（成交、取消、拒絕）；不應根據一次 REST position snapshot 推斷終態。
3. **查兩腿實際持倉**：分別記下 Entropy 和 hedge venue 的持倉與淨曝險。剛成交後 REST 有可能落後 WS；原版有 5 秒 grace skip，不能把跳過查詢當成成功對帳。兩腿都要完成有效查詢。
4. **處理實際淨曝險**：若有單邊殘餘倉位，由操作人根據當前成交與價格自行決定是否減倉，之後重新查兩腿持倉及活動訂單。不要在訂單結果仍未知時盲目重複下單。
5. **恢復方式**：只有確認訂單均已終結、兩腿持倉已核對，且沒有不受控的程序後，才由操作人決定重啟。現有 Draft PR #6 的 unresolved gate 沒有自動解除機制；**程序重啟會初始化這個記憶體 gate，不能把重啟當成自動恢復的安全證明。**
6. **留存證據**：保留 UTC 時間、交易所訂單 ID／client ID（如果取得）、原始回覆、兩腿持倉前後變化與人工處理記錄。若證據不足，保持停止新交易。

不在 P0-03 實作完整自動訂單恢復、跨程序 ledger、無證據的自動補單。
